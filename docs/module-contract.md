# 平台 BFF 架构与安全边界

## 设计

该模块嵌入 233 的 `netops-littleProgram` Flask 宿主应用，复用统一登录、JWT、组织、菜单和审计。它是浏览器与内网服务之间唯一的业务代理，不将采集库、AIOps 或 ClickHouse 账号下发给浏览器。

## 数据与依赖

| 目标 | 用途 | 访问方向 |
| --- | --- | --- |
| 233 MySQL 历史 schema `anbo_wx` | 用户、组织、权限、审计；物理库名兼容保留 | 本机 |
| 236 `18086` / `3339` | 采集状态与采集业务数据 | 233 → 236 |
| 20 `18080` | AIOps 代理，使用服务间签名 | 233 → 20 |
| 212 `8123` | ONU/OLT/Radius 历史分析 | 233 → 212 |

## 端口与安全

用户入口为 **233:5772**。Gunicorn/BFF `7001` 只绑定 `127.0.0.1`；233 MySQL `6603` 仅允许必要管理网段。233→20 的共享签名密钥只能保存于受控运行配置，不写入 Git。

拓扑接口会同时公开链路方向、端口、实时可达状态和最后核验的访问控制说明：20 的 `18080` 仅允许 233/回环，213 的 `3306`/`18190` 已由端口守卫限制，236 与 212 的主机级策略仍明确标为待收敛/待审计，不能因链路可达而误判为已受限。
